# Общий контракт для двух вариантов `core`

## Граница

- `raw` остаётся без изменений; модель собирается в `core` из исходных строк. Ответы на аналитические вопросы считаются из `core`, а `mart` используется только при необходимости. Источник: [задание](../handout.md).
- Оба варианта должны показать судьбу всех восьми таблиц `raw` и не терять записи молча. Основание: [D03](decision-log.md#d03-общий-охват-вариантов), [D06](decision-log.md#d06-сохранность-неполных-записей).
- Будущие пять вопросов пока неизвестны; структура не должна кодировать только текущие пять ответов. Источник: [вопросы](../tasks.md).

## Источники и уровень строки

| Источник `raw` | Исходный уровень и ключ для сверки | Обязательство варианта |
| --- | --- | --- |
| `orders` | заказ, `order_id` | Сохранить заказ и статус, даже без позиций. |
| `customers` | запись покупателя, `customer_id`; покупатель — `customer_unique_id` | Сохранить обе идентичности и адресные поля. |
| `order_items` | единица товара, `(order_id, order_item_id)` | Сохранить цену, доставку, товар, продавца и срок отгрузки. |
| `order_payments` | платёж, `(order_id, payment_sequential)` | Сохранить способы и суммы отдельно от цены товаров. |
| `order_reviews` | отзыв, `(review_id, order_id)` | Сохранить несколько отзывов на заказ. |
| `products` | товар, `product_id` | Сохранить товар без категории и его атрибуты. |
| `sellers` | продавец, `seller_id` | Сохранить продавца и адресные поля. |
| `product_category_translation` | перевод категории, `product_category_name` | Сохранить перевод и исходное название категории. |

Поля и описания источников приведены в [DDL raw](../../../scripts/init/02_raw_ddl.sql); фактическая уникальность перечисленных ключей для текущих CSV проверена в [профиле данных](data-profile.md). Правила единицы товара, покупателя и отзыва — [D07–D09](decision-log.md).

## Общие определения показателей

| Показатель | Правило | Происхождение |
| --- | --- | --- |
| Выручка | Сумма `price` единиц товаров во вручённых заказах; доставка исключена. | [D05](decision-log.md#d05-выручка) |
| Средний чек | Среднее по вручённым заказам от суммы `price + freight_value` всех единиц заказа. | [D16](decision-log.md#d16-средний-чек) |
| Повторный заказ | Минимум два заказа одного `customer_unique_id`, независимо от статуса. | [D07](decision-log.md#d07-покупатель), [D17](decision-log.md#d17-повторный-заказ) |
| Товарная строка | Одно сочетание `(order_id, product_id, seller_id)`; число единиц — число исходных позиций в нём. | [D08](decision-log.md#d08-единица-товара-и-позиция), [D18](decision-log.md#d18-строка-и-единица-товара) |
| Категория в отчёте | Пустая → «Неизвестно»; без перевода → исходное название; сумма категорий равна общей выручке. | [D10](decision-log.md#d10-неизвестные-и-непереведённые-категории) |

## Сборка и проверки

- Непустые числовые и временные поля приводятся к подходящим типам; пустые необязательные поля становятся `NULL`; некорректное непустое значение прерывает сборку с явной ошибкой. [D13](decision-log.md#d13-преобразование-типов).
- Сборка из `raw` должна быть повторяемой и менять только объекты `core`, которыми управляет её скрипт. [D14](decision-log.md#d14-повторяемая-сборка).
- Исходные ключи и имя таблицы-источника остаются доступны для сверки строки модели с `raw`. [D15](decision-log.md#d15-прослеживаемость-до-источника).
- Для заказов без позиций, товаров без категории и расхождений платежей должны быть явные проверки качества. [D06](decision-log.md#d06-сохранность-неполных-записей), [D11](decision-log.md#d11-платежи-и-расхождения).
- Суммы по месяцам и категориям сверяются с общей выручкой. Отчёт по месяцам должен включать месяц без заказов через календарный диапазон. Источник: [вопросы](../tasks.md).
