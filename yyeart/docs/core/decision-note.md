# Краткая записка о решениях

Выбрана нормализованная модель `core`: заказ, единица товара, платёж и отзыв хранятся на своих исходных уровнях, а покупатель определяется устойчивым `customer_unique_id`. Исходные ключи сохранены; для отзыва используется пара `(review_id, order_id)`, поскольку один `review_id` в данных повторяется. Денежные итоги не записаны повторно в заказ: выручка считается по ценам товаров вручённых заказов, средний чек — по стоимости товаров вместе с доставкой. Пустая категория остаётся «Неизвестно», непереведённая показывается под исходным названием. Альтернатива с предрассчитанными фактами заказа не выбрана для личного варианта: она требует сверять дублированные суммы, но не избавляет от позиций в отчётах по продавцам и категориям. Повторная сборка прошла; числа строк всех восьми источников совпали с `core`, а пять опубликованных контролей получены запросами из модели. Основания — [ADR-0001](../adr/0001-normalized-core.md), [журнал](decision-log.md) и [проверка](../../model/results/validation.txt).
