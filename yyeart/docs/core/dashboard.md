# Концепция дашборда продаж

**Пользователь:** коммерческий руководитель Capibara. **Решение:** увидеть изменение продаж по времени, продавцам и категориям и отличить рост числа заказов от роста стоимости заказа. Дашборд опирается на реализованные [таблицы `core`](../../model/build_core.sql); SQL для первых пяти показателей приведён в [ответах](answers.md). [Локальная реализация](../../dashboard/app.py) читает `core` напрямую; инструкция запуска находится в [README](../../README.md#локальный-дашборд-продаж).

| Показатель | Формула и уровень расчёта | Источник `core` | Вопрос для руководителя |
| --- | --- | --- | --- |
| Выручка | Сумма `order_items.price` по единицам товаров заказов `delivered`. Уровень — единица товара; месяц берётся из даты оформления заказа. | `order_items`, `orders`, при срезе — `products`, `sellers`. | Какие месяцы, категории и продавцы дают товарную выручку? |
| Число заказов | `count(DISTINCT order_id)` всех статусов за период. Уровень — заказ. | `orders`. | Меняется ли поток заказов отдельно от выручки вручённых заказов? |
| Средний чек | Среднее по вручённым заказам от `sum(price + freight_value)` их единиц товара. Сначала сумма на уровне заказа, затем среднее. | `orders`, `order_items`. | Изменяется ли стоимость одного вручённого заказа? |
| Доля повторных покупателей | Число покупателей с минимум двумя заказами любого статуса / число покупателей × 100. Уровень — покупатель за выбранный период. | `customer_records`, `orders`. | Растёт ли возвращаемость по числу заказов? |
| Доля категории в выручке | Выручка категории / выручка всех категорий за тот же период × 100. Категория определяется по исходному коду; пустая — «Неизвестно». | `order_items`, `orders`, `products`, `category_translations`. | Не держится ли рост на одной категории и сколько остаётся неклассифицированным? |

**Срезы:** месяц оформления, штат продавца, продавец и категория товара. Для повторности период должен применяться **до** подсчёта заказов на покупателя; иначе показатель отвечает на другой вопрос. Источник определения повторности — [D17](decision-log.md#d17-повторный-заказ).

**Правила интерфейса:** период действует на все показатели; по умолчанию — сентябрь 2016 — август 2018. Штат продавца, продавец и категория действуют только на выручку и её разрезы. Число заказов, средний чек и повторность остаются показателями всех заказов периода. Доля категории имеет знаменатель из всех категорий за выбранный период и выбранных продавцов до фильтра категории. Пустая категория доступна как отдельное значение «Неизвестно». За 24 месяца повторность составляет 2 987 / 96 090 = 3,11%; опубликованный контроль 3,12% относится ко всей выгрузке.

**Аддитивность:** выручку можно складывать по непересекающимся месяцам, продавцам и исходным кодам категорий, поскольку каждая единица товара имеет одного продавца и один товар. Число уникальных заказов нельзя складывать по продавцам и категориям: один заказ может содержать товары нескольких продавцов и категорий ([задание](../handout.md)). Средний чек, доля повторных покупателей и доля категории также не складываются по срезам; их нужно пересчитывать из числителя и знаменателя выбранного среза.
